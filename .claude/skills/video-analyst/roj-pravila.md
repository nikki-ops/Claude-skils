# Общие правила роя video-analyst

Каждый агент роя читает этот файл перед работой.

## Материалы

Папка ролика: `render/_istochniki/<slug>/`.
- `video.*`, `video.info.json` — ролик и метаданные;
- `*.vtt` / `*.srt` — субтитры, если были;
- `kadry/hook_*.jpg` (0–3 с, 8 кадров/с), `kadry/sec_*.jpg` (1 кадр/с), `kadry/cut_*.jpg`, `skleyki.txt` — кадры и склейки;
- `audio.wav`, `pauzy.txt`, `gromkost.txt` — звук;
- `material.md` — чего не хватает;
- `otchety/` — отчёты агентов.

Кадры смотри через Read (это изображения). Если нужного файла нет — сделай его сам через `ffmpeg`/`ffprobe` в той же папке.

## Доказательность (главное правило)

- Каждая находка — с доказательством: таймкод (`0:02.4`), файл кадра, цитата из транскрипта, число или ссылка.
- Нет доказательства — это гипотеза, помечай `[гипотеза]`.
- Не выдумывай. «Не удалось определить» — нормальный ответ; выдумка, пойманная аудитором, — штраф.

## Формат отчёта (режим АНАЛИЗ)

Файл `otchety/<NN>-<rol>.md`:

```markdown
# <NN> <Роль> — <slug>

## Находки
| ID | Время | Находка | Доказательство | Уверенность |
|---|---|---|---|---|
| 03-1 | 0:00.0–0:00.8 | ... | kadry/hook_01.jpg; «цитата» | высокая |

## Что взять в наш мультик
- ...

## Чего не удалось проверить
- ...
```

ID — номер агента и номер находки (`03-1`, `03-2`…), по ним ссылается аудит.

## Перекрёстный аудит (режим АУДИТ)

Файл `otchety/audit-<NN автора>-ot-<NN аудитора>.md`. Аудитор обязан:

1. **Перепроверить каждую находку автора** по материалам и поставить вердикт: `подтверждаю` / `уточняю` (что не так) / `опровергаю` (с доказательством).
2. **Найти минимум две новые скрытые детали** в зоне автора, которые тот упустил: на каждую находку автора, которая вызвала сомнение или интерес, — две своих более глубоких. Детали — с доказательствами, ID вида `A04-1`.
3. Если честно нашлось меньше двух подтверждаемых деталей — так и написать и перечислить, что проверено. **Придумывать детали ради квоты запрещено** — это хуже, чем не найти.
4. Соревнование — в глубине, а не в объёме: одна неочевидная деталь с точным таймкодом стоит больше пяти общих слов.

```markdown
# Аудит отчёта <NN автора> — проверяет <NN аудитора>

## Проверка находок
| ID | Вердикт | Комментарий и доказательство |
|---|---|---|

## Новые детали, которые автор упустил
| ID | Время | Деталь | Доказательство |
|---|---|---|---|

## Итог
Подтверждено X из Y, опровергнуто Z, новых деталей N.
```

## Ответ на аудит (режим ОТВЕТ НА АУДИТ)

Допиши в свой отчёт раздел `## Ответ на аудит`: по каждому спорному пункту — `принимаю` (и исправь находку) или `защищаю` (с новым доказательством). Новые детали аудитора тоже проверь и отметь.

## Авторские права

Рой изучает приёмы, а не копирует ролик. В наш мультик переносятся тип хука, ритм, структура, длительность кадров, настроение. Сюжет, персонажи, реплики, графика, шрифты под лицензией и музыка источника не копируются. Музыка для нашего мультика — только из `muzyka/` с правом на использование.

## Ответ дирижёру

Последним сообщением верни: путь к файлу, число находок (или вердиктов) и 3 самые сильные находки одной строкой каждая.
