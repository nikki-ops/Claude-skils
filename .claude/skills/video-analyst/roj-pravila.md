# Общие правила роя video-analyst

Каждый агент роя читает этот файл перед работой.

## Материалы

Папка ролика: `render/_istochniki/<slug>/`.
- `video.*`, `video.info.json` — ролик и метаданные;
- `*.vtt` / `*.srt` — субтитры, если были;
- `kadry/hook_*.jpg` (0–3 с, 8 кадров/с), `kadry/sec_*.jpg` (1 кадр/с), `kadry/cut_*.jpg`, `skleyki.txt` — кадры и склейки;
- `audio.wav`, `pauzy.txt`, `gromkost.txt` — звук;
- `material.md` — чего не хватает;
- `kesh/meta.md`, `kesh/set.md` — кэш метаданных и всех открытых ссылок (пишет Скаут, дополняют 6 и 9);
- `otchety/vyzhimka.md` — сжатая выжимка речи с таймкодами (Транскрибатор);
- `otchety/svodka.md` — сводка всех отчётов (дирижёр);
- `otchety/` — отчёты агентов.

Кадры смотри через Read (это изображения), по правилам экономии ниже. Если нужного файла нет — сделай его сам через `ffmpeg`/`ffprobe` в той же папке.

## Доказательность (главное правило)

- Каждая находка — с доказательством: таймкод (`0:02.4`), файл кадра, цитата из транскрипта, число или ссылка.
- Нет доказательства — это гипотеза, помечай `[гипотеза]`.
- Не выдумывай. «Не удалось определить» — нормальный ответ; выдумка, пойманная аудитором, — штраф.

## Протокол экономии (обязателен)

Цель — разбор одного ролика в пределах лимитов подписки Claude Pro.

### 1. Лимит раундов
- Раунд 1 — анализ, раунд 2 — перекрёстный аудит. Третьего раунда, ответов на аудит и повторных проверок нет.
- Аудитор проверяет отчёт автора **один раз**, находит **2** скрытые детали или ошибки, **сам дописывает** их в отчёт автора (раздел `## Аудит (агент NN)`) и закрывает спор.

### 2. Сжатый контекст — что читает агент
| Агент | Читает | Не читает |
|---|---|---|
| все | `material.md`, `kesh/meta.md`, `otchety/vyzhimka.md`, свой отчёт | `otchety/transkript.txt` (архив), чужие отчёты целиком |
| волна 2 | + `otchety/svodka.md` | — |
| аудитор | + отчёт, который проверяет | остальные отчёты |
| 10 Режиссёр | `svodka.md`, `vyzhimka.md`, `kesh/meta.md`, бриф | полные отчёты (только Grep по ID, если в сводке не хватает) |

Полный транскрипт открывает только Транскрибатор.

### 3. Объединённые вызовы
- 7 Визионер + 8 Стилист — один агент `va-78-vizual`, один отчёт.
- 5 Аудиофил + 6 Музыкальный юрист — один агент `va-56-zvuk`, один отчёт.
- Аудит отчётов 2 и 7+8 — один вызов `va-56-zvuk`.
- Аудит сценария и правка сценария — один вызов `va-03-huk-master`.

### 4. Кэш и запрет повторного чтения сети
- По ссылке ролика и на страницы платформы ходит **только Скаут** (`va-01-skaut`) и только если `kesh/meta.md` ещё пуст.
- Всё полученное из сети записывается в кэш: `kesh/meta.md` — метаданные, `kesh/set.md` — каждая ссылка → 1–2 строки сути.
- Перед любым WebSearch/WebFetch — прочитай `kesh/set.md`. Ссылку, которая там уже есть (или не открылась), **повторно не запрашивай**.
- Лимиты сети: Скаут ≤ 3 запроса, Трендолог ≤ 5 поисков + 3 страницы, Звук ≤ 3 поиска. Остальные агенты в сеть не ходят.

### 5. Картинки и инструменты
- Сначала `obzor.jpg` и тайлы (`ffmpeg … tile=`), отдельные кадры — только для спорных мест. Не больше **8 просмотров картинок** на агента.
- Не больше **25 вызовов инструментов** на агента. Не устанавливай пакеты ради «а вдруг»: чего нет в `material.md` — значит недоступно.
- Временные скрипты и картинки — в папку ролика (`tmp/`), не плодить копии.

### 6. Размеры ответов
- Отчёт: таблица находок ≤ 20 строк, разделы «Что взять» и «Чего не удалось проверить» ≤ 5 пунктов каждый.
- Аудит: ≤ 15 строк.
- **Ответ дирижёру: не больше 5 строк** — путь к файлу, число находок, 3 главные находки по одной строке. Подробности — только в файле.

## Формат отчёта (режим АНАЛИЗ)

Файл `otchety/<NN>-<rol>.md`:

```markdown
# <NN> <Роль> — <slug>

## Находки
| ID | Время | Находка | Доказательство | Уверенность |
|---|---|---|---|---|
| 03-1 | 0:00.0–0:00.8 | ... | kadry/hook_01.jpg; «цитата» | высокая |

## Что взять в наш мультик
- ...

## Чего не удалось проверить
- ...
```

ID — номер агента и номер находки (`03-1`, `03-2`…), по ним ссылается аудит.

## Перекрёстный аудит (режим АУДИТ)

Аудит **дописывается в отчёт автора** разделом `## Аудит (агент <NN аудитора>)` — отдельного файла нет. Аудитор обязан:

1. **Перепроверить каждую находку автора** по материалам и поставить вердикт: `подтверждаю` / `уточняю` (что не так) / `опровергаю` (с доказательством).
2. **Найти 2 новые скрытые детали или ошибки** в зоне автора, которые тот упустил. Детали — с доказательствами, ID вида `A04-1`.
3. Если честно нашлось меньше двух подтверждаемых деталей — так и написать и перечислить, что проверено. **Придумывать детали ради квоты запрещено** — это хуже, чем не найти.
4. Соревнование — в глубине, а не в объёме: одна неочевидная деталь с точным таймкодом стоит больше пяти общих слов.

```markdown
## Аудит (агент <NN аудитора>)

### Проверка находок
| ID | Вердикт | Комментарий и доказательство |
|---|---|---|

### Новые детали, которые автор упустил
| ID | Время | Деталь | Доказательство |
|---|---|---|---|

### Итог
Подтверждено X из Y, опровергнуто Z, новых деталей N.
```

## Ответа на аудит нет

Спор закрывается аудитом. Спорные пункты решает дирижёр по доказательствам, без новых запусков агентов.

## Авторские права

Рой изучает приёмы, а не копирует ролик. В наш мультик переносятся тип хука, ритм, структура, длительность кадров, настроение. Сюжет, персонажи, реплики, графика, шрифты под лицензией и музыка источника не копируются. Музыка для нашего мультика — только из `muzyka/` с правом на использование.

## Ответ дирижёру

Не больше 5 строк: путь к файлу, число находок (или вердиктов) и 3 самые сильные находки по одной строке.
