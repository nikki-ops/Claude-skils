# 3D-декорации на GLSL в Higgsedit

Каждая локация — это файл `.glsl`, который подклеивается к `lib.glsl` и рисуется шейдером на прямоугольнике во весь кадр. Рендер идёт на CPU (llvmpipe). Рабочие примеры в `templates/boat-lantern/edit3d/`:
- `terrace.glsl` — терраса ресторана: дощатый настил, белые перила, полосатый зонт, столик, стулья, море, небо с облаками;
- `booth.glsl` — будка букмекера: бордовые стены, сукно с латунью, лампы с ореолом, доска объявлений, рация, которая трясётся;
- `sea.glsl` — регата: 4 яхты с номерами на парусах, старое корыто №7 с дымом, шторм, переворот лидеров, финишные шесты с клетчатыми флагами, буйки, кучевые облака;
- `cliff.glsl` — мыс: край скалы, трава, камни, прожектор на треноге с лучом и ореолом, море в 30 м внизу.

## Правила шейдера (GLSL ES 1.00)
- Файл определяет `vec4 pixel(vec2 uv)`, функцию `main()` дописывает обёртка. `uv` идёт от 0 до 1, ось y смотрит вниз. `u_resolution` — размер узла, `u_time` — **глобальное** время (локальное время сцены — вычесть её начало).
- Любой числовой параметр (`cam: 0`) превращается в `uniform u_cam`. Объявлять его самому нельзя. Анимация — через `animate: [{property:"effectParam", effectIndex:0, effectParam:"cam", keyframes:[...]}]` с easing `linear`, если GLSL сам сглаживает.
- Нельзя: `texture()`, `round()`, `trunc()`, `tanh()`, `inverse()`, `transpose()`, `%`, побитовые операции. Циклы — только с константной границей. Глобальные переменные инициализируются только константами.
- Ошибка компиляции выглядит как `0:LINE(COL)`. LINE считается с учётом 8 строк преамбулы и всех строк `lib.glsl`.
- Выход премультиплицированный: `vec4(col*a, a)`.

## Библиотека (`lib.glsl`)
- База Content Factory: `sdSphere/Ellipsoid/Capsule/RoundBox/Cylinder/Torus`, `smin`, `opU`, `rot`, `hash2`, `noise2`, `lin()`, `screenP`, `camRay`, `calcNormal`, `march` (96 шагов, контур-«чернила» по краю силуэта), `softShadow`, `calcAO`, `shade`, `grade`, `grain`.
- Добавлено под этот стиль:
```glsl
vec3 hexc(float r,float g,float b){ return lin(vec3(r,g,b)/255.0); }
float softSh(vec3 ro, vec3 rd, float k){ /* 40 шагов, t<=12 */ }
// Мягкий «мультяшный» ламберт: smoothstep(-0.10,0.30,NdotL) * тень, фиолетовая тень, AO
vec3 shadeR(vec3 pos, vec3 n, vec3 alb, vec3 L, vec3 keyC, vec3 fillC, vec3 bounceC, vec3 shTint, float aoS);
// Грейд: насыщенность, контраст вокруг 0.45, подъём чёрного
vec3 post(vec3 c, float sat, float con, vec3 blk);   // обычно post(col, 1.15, 1.1, vec3(0.02,0.015,0.04))
```

## Свет и цвет (по `analysis/Ref_3D_render-look_analysis.md`)
- Ключевой свет — тёплое солнце, сбоку и чуть сзади: `L = normalize(vec3(0.55, 0.75, 0.45))`, цвет кремовый.
- Заполняющий свет — цвета неба (голубой). Отражённый снизу — тёплый, от пола.
- Тени фиолетовые: `shTint` около `hexc(74,61,94)` (#4A3D5E).
- Обводка 3D: тёмно-лавандовая `#3b2a40` с 60–80 % непрозрачности, ширина `outlineW` около 0.006. Чуть «кистевая».
- Небо: вертикальный градиент `#316fe5 → #a9d4fb` (снаружи) или `#5AB0F6 → #B0E1FF`. Облака кучевые: светлый кремовый верх `#fef2da`, сиреневый низ `#ccd2ea`, плоское дно, тонкая рваная обводка.
- Дымка к горизонту: даль светлеет и голубеет, контраст падает. Это `grade(col, bg, t, hazeStart, haze, lift)` или своя функция по дистанции. Без дымки нет глубины.
- Насыщенность высокая. «Серо и блекло» — главный упрёк юзера (так было с BrickToy).

## Глубина резкости: двухслойный `Set3D` (`rig.jsx`)
```jsx
const [bg, fg] = Set3D({ set: "ter", dur, p: {...камера}, keys: { rx: [[0, a], [dur, b]] }, focus: 3.4, blur: 7 });
<Sc ...>{bg}<Toon .../>{fg}</Sc>
```
- **Дальний слой.** Шейдер с `layer=1` на прямоугольнике 556×976 внутри фрейма 540×960 со `scale` 2 (`origin="top-left"`). Сверху эффект `blur`. Рендерится примерно вдвое быстрее, апскейл скрыт размытием.
- **Ближний слой.** Тот же шейдер с `layer=2` на полный кадр. Альфа = `1 - smoothstep(focus, focus*1.35, t)`: виден только то, что ближе фокуса, и оно резкое.
- В конце каждой сцены:
```glsl
col=clamp(col,0.0,1.0);
if(u_layer>1.5){ float a=1.0-smoothstep(u_focus,u_focus*1.35,tt); return vec4(col*a,a); }
return vec4(col,1.0);
```
- 2D-персонажи рисуются **между** `bg` и `fg`. Тогда стол, стойка или подушка перекрывают их, как в 3D.
- `focus = null` — один резкий слой (для дальних общих планов).

## Камера сцены
`DEF[set]` хранит позицию `rx, ry, rz`, цель `tx, ty, tz` и `lens` (около 1.0–1.1, примерно 35 мм). Камера всегда движется: ключи в `keys`. Параллакс за счёт настоящего 3D. 2D-камера `Sc` (`cam: {s, x, y, r}`) — только для «наездов» поверх.

## Производительность
- Около 96 шагов марша, 32–40 шагов тени, 5 отсчётов AO. Несколько десятков примитивов, не сотни.
- Оценки по сложности: стандартная песочница 0.45–3.6 с/кадр, XL примерно в 4 раза быстрее.
- Одиночный `higgsedit frame` включает компиляцию шейдера (~10 с). Мерить скорость через `render --range` на 10–30 кадрах.
- Ускорители:
  - ограничивающие объёмы (`if(sdBox(q-c,h) < r.x)`), чтобы не считать дальние группы;
  - тень на полу считать только рядом с объектами;
  - нормаль по тетраэдру (4 вызова `map`);
  - AO по 3 отсчётам.
- Артефакты:
  - «древесные разводы» или кольца на полу — шаг тени слишком крупный или из-за ограничения расстояния до края ячейки. Делать простую тень `k` около 12–18, шаг `clamp(h, 0.015, 0.22)`;
  - чёрная кромка при whip-сдвиге — не сдвигать слой, использовать масштаб и размытие.
