# one-click-director — сборка ролика одной командой

## Пути проекта

- Вход: `stsenarii/<id>.md`, `golos/<id>.*`, трек из `muzyka/` (+ `<трек>.litsenziya.md`), `render/stil/stil.md`, `render/assets/<id>/`.
- Проект Remotion: `render/remotion/` (композиция с `id="<id>"`), сжатые ассеты `render/remotion/public/<id>/`, тайминги `render/remotion/src/data/<id>.timing.json`.
- Выход: `gotovo/<id>.mp4` и обложка `gotovo/<id>-oblozhka.png`.

`<id>` — имя ролика (`01-nazvanie`). Если пользователь не назвал ролик — возьми последний сценарий в `stsenarii/` (кроме `*.analiz.md`) и скажи, какой выбран.

## Команда

Пользователь говорит, например: «собери 01-kot» — и ты выполняешь весь конвейер ниже без дополнительных вопросов, пока не упрёшься в то, что может дать только он (озвучка, трек, лицензия, картинки).

## Конвейер

### 1. Проверка готовности

```bash
python3 .claude/skills/one-click-director/scripts/proverka.py <id>
```

✔ — готово, ✖ — блокирует рендер, ⚠ — предупреждение. Код выхода 1 — есть ✖.

### 2. Автоисправление

Что можно сделать самому — делай и перезапускай проверку:

| Проблема | Действие |
|---|---|
| Нет проекта Remotion | навык `remotion-create` → проект в `render/remotion/` |
| Нет зависимостей | `cd render/remotion && npm install` |
| Нет композиции | добавить `<Composition id="<id>">` по шаблону из навыка `audio-sync-master` (сцены из таймингов, кадры из сценария) |
| Нет сжатых ассетов / новые файлы | навык `asset-compressor` (картинки, голос, музыка) |
| Нет таймингов / устарели | навык `audio-sync-master` |
| Нет библии стиля (⚠) | навык `ai-art-prompter`, если нужно генерировать картинки |

Чего самому не сделать — **остановись и попроси** у пользователя, перечислив списком: нет сценария, нет озвучки, нет трека или файла лицензии на него (без лицензии трек не используется: или рендер без музыки, или другой трек из `muzyka/`), нет картинок для кадров.

### 3. Превью перед рендером

```bash
cd render/remotion
npx remotion still <id> ../../gotovo/<id>-proverka.png --frame=15
```

Посмотри кадр (Read): персонажи на месте, текст в безопасной зоне, ничего не обрезано. Удали файл проверки после.

### 4. Рендер

```bash
cd render/remotion
npx remotion render <id> ../../gotovo/<id>.mp4 --codec=h264 --crf=23 --audio-codec=aac --audio-bitrate=192k
```

H.264 + CRF 23 — лёгкий файл, который открывается на любом телефоне. Для максимального качества — `--crf=18`. Подробности и ошибки рендера — навык `remotion-render`. Если ролик собран в HyperFrames (`render/<project>/` с `index.html`), рендер — `npx hyperframes render --output ../../gotovo/<id>.mp4` (навык `hyperframes-cli`).

### 5. Обложка

```bash
npx remotion still <id> ../../gotovo/<id>-oblozhka.png --frame=<кадр>
```

Кадр — самый выразительный момент: кульминация из сценария или сцена с крупным планом героя (по таймингам — `from` + половина `durationInFrames`). Если в проекте есть отдельная композиция обложки `<id>-oblozhka` — рендерить её.

### 6. Проверка результата

```bash
ffprobe -v error -show_entries format=duration,size:stream=codec_name,width,height -of json ../../gotovo/<id>.mp4
```

- длительность = `dlitelnost` из таймингов (±0.1 с);
- есть видео (h264) и аудио (aac) потоки;
- разрешение как в композиции (1080×1920 для Shorts/TikTok);
- посмотри 3 кадра (начало, середина, конец): `ffmpeg -ss <t> -i gotovo/<id>.mp4 -frames:v 1 <scratchpad>/k.png`.

### 7. Отчёт пользователю

Путь к ролику и обложке, длительность, размер в МБ, что было исправлено автоматически, предупреждения (⚠). Готовые файлы в git не коммить без просьбы — видео тяжёлые.
